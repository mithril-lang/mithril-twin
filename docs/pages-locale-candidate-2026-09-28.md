# Twin Pages locale and mobile candidate — 2026-09-28

This branch ports the Mithril Web Twin's mobile layout correction and `?lang=` / `mf_locale` selection to the separate GitHub Pages viewer. It keeps the project-site base `/mithril-twin/`, the selected `?doc=` sample, and the original synthetic data and display-only boundary. Non-English locales show an explicit localized notice that some viewer content remains in English.

The Pages build (`GITHUB_PAGES=true npm run build`) and preview (`GITHUB_PAGES=true npm run preview -w @mithril-twin/viewer`) passed at `/mithril-twin/`. Switching Arabic to Japanese preserved `?doc=polaris-enterprise`, updated `?lang=` and `mf_locale`, and the cookie restored Japanese without a language query. See `twin-pages-mobile-ar-candidate-2026-09-28.png`.

The follow-up candidate exposes the object detail panel on mobile and translates 85 primary viewer control strings across all 22 locales. `twin-make-locales-candidate-2026-09-28.json` records a fresh 390 px browser visit for each locale: translated status and Details button, language and RTL direction, detail-panel opening, no horizontal overflow and no page errors. Japanese and Arabic captures are `twin-make-ja-mobile-candidate-2026-09-28.png` and `twin-make-ar-mobile-candidate-2026-09-28.png`. `.mith` labels and identifiers are deliberately left in their source language. The Japanese strings are authored; the other 20 translations were generated and need semantic review.

The package typechecks, its 62 parser and 42 viewer tests pass, lint is clear, and the Pages build succeeds.

This is a candidate, not publication approval. ScaleGrid, lens/inspector panels, secondary views and generated explanations still need localization and interaction review. The old live Pages build and `twin.mithril.fund` still need a source-by-source comparison before this branch can be merged into auto-publishing `main` or counted as a Twin site/locale receipt.
